Day and night are one palette with a single control.

Day values are lifted verbatim from app/globals.css — nothing was re-picked. Night is derived in oklab from the same hues, raised only as far as contrast requires.

Day cobalt at #245bff would land near 1.9 : 1 on the night surface — unreadable. Night cobalt is raised to #5b87ff for that reason alone; the hue is unchanged. No text ever renders inside the transition band, so the mid-interpolation greys are never a contrast surface.

The interpolation

@property --night { syntax: "<number>"; inherits: true; initial-value: 0 }

:root {
  --d-surface: #f7f8fc;  --n-surface: #0b0e16;
  --d-ink:     #111522;  --n-ink:     #e8edfb;
  --d-cobalt:  #245bff;  --n-cobalt:  #5b87ff;

  --surface: color-mix(in oklab, var(--d-surface),
              var(--n-surface) calc(var(--night) * 100%));
  --ink:     color-mix(in oklab, var(--d-ink),
              var(--n-ink)     calc(var(--night) * 100%));
  --cobalt:  color-mix(in oklab, var(--d-cobalt),
              var(--n-cobalt)  calc(var(--night) * 100%));
}

Registering --night as a <number> is what makes it animatable at all — an unregistered custom property jumps between values instead of interpolating. oklab keeps the midpoint from going muddy the way sRGB mixing does.
